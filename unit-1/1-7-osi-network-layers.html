1.7 • OSI Model and Network Layers

How Computers Communicate Across Network Layers

The Open Systems Interconnection (OSI) model divides network communication into seven layers. Each layer has a different responsibility, and together they explain how data moves from an application on one computer to an application on another.

Big idea

Communication is easier to understand when it is divided into layers.

The OSI model gives each part of network communication a job. Applications create data, lower layers prepare it for delivery, network devices move it, and the receiving computer rebuilds the data as it moves back up the layers.

The OSI model

OSI stands for Open Systems Interconnection. It is a conceptual model used to describe how computers communicate over a network. The model has seven layers. Each layer provides services to the layer above it and uses services from the layer below it.

When data is sent, it moves down the layers on the sender's computer. When it arrives, it moves up the layers on the receiver's computer. This process is called encapsulation and decapsulation.

The Application layer is the layer closest to the user. It provides network services to applications such as web browsers, email clients, file-transfer programs, and messaging applications.

This does not mean that the application itself is the entire layer. The layer contains the network protocols and services that applications use to communicate.

Examples: HTTP and HTTPS for web traffic, DNS for resolving domain names, SMTP for sending email, IMAP and POP3 for retrieving email, and SSH for secure remote access.

Security relevance: Application-layer attacks target the services and data that users interact with. Examples include phishing, malicious requests, SQL injection, cross-site scripting, insecure authentication, and abuse of exposed APIs. Strong authentication, input validation, authorization, secure coding, and logging help protect this layer.

Memory clue: The Application layer is where network-aware applications request services such as web pages, name lookups, and remote access.

The Presentation layer handles how data is represented. It can translate data between formats, encode and decode information, compress data, and encrypt or decrypt data.

Two computers may need to agree on how characters, numbers, images, or structured information are represented. The Presentation layer helps make sure the receiving system can interpret the data correctly.

Examples: character encoding such as UTF-8, data formats such as JSON and XML, image formats such as JPEG and PNG, compression, and encryption formats used by secure communication.

Security relevance: Encryption protects confidentiality, while integrity checks help detect changes to data. Weak encoding, unsafe deserialization, format confusion, and poor certificate handling can create vulnerabilities. TLS is often discussed near this layer because it protects the representation and exchange of application data, even though real protocols do not always fit perfectly into one OSI layer.

Memory clue: The Presentation layer makes data understandable, usable, compressed, and protected.

The Session layer establishes, manages, and ends communication sessions between applications. A session is an organized conversation that can remain active while multiple messages are exchanged.

Session responsibilities can include starting a conversation, keeping track of its state, controlling who is sending data, synchronizing communication, and recovering or closing the session.

Examples: login sessions, RPC sessions, long-running connections, checkpoints, and mechanisms that allow a conversation to resume after an interruption. In modern networks, session responsibilities are often built into application protocols rather than appearing as one separate protocol.

Security relevance: Session hijacking, stolen session cookies, weak timeouts, predictable session identifiers, and failure to invalidate sessions after logout can allow an attacker to act as another user. Secure random session tokens, expiration, reauthentication for sensitive actions, and protected cookies reduce these risks.

Memory clue: The Session layer keeps track of the conversation between applications.

The Transport layer provides communication between applications running on different devices. It can divide data into smaller pieces, identify the destination application with port numbers, manage flow, detect errors, and provide reliable delivery when the protocol supports it.

The two transport protocols most commonly discussed are TCP and UDP.

TCP — Transmission Control Protocol: TCP is connection-oriented. It establishes a connection before sending application data, numbers segments, acknowledges received data, retransmits missing data, manages flow, and helps control congestion. TCP is useful when data must arrive reliably and in order, such as web pages, email, file transfers, and SSH sessions.

UDP — User Datagram Protocol: UDP is connectionless and has less overhead. It does not guarantee delivery, ordering, or retransmission. UDP is useful when speed and low delay matter or when the application handles reliability itself, such as DNS queries, streaming, voice traffic, online games, and some real-time services.

Ports: A port number identifies the application or service that should receive transport-layer data. An IP address identifies a host, while a port identifies a service on that host. For example, HTTPS commonly uses TCP port 443, DNS commonly uses UDP or TCP port 53, and SSH commonly uses TCP port 22.

Security relevance: Firewalls often filter traffic by protocol, source, destination, and port. Port scanning can reveal available services. Attacks such as SYN floods, connection exhaustion, UDP floods, and abuse of exposed services target transport behavior. Secure configurations should expose only the ports that are needed.

Memory clue: The Transport layer delivers data from one application to another using ports, reliability, and flow control.

The Network layer moves packets between different networks. It uses logical addressing and routing so data can travel from a source network to a destination network.

IP addresses identify the source and destination locations for network traffic. IPv4 uses 32-bit addresses such as 192.168.1.25. IPv6 uses 128-bit addresses such as 2001:db8::1. Routers inspect destination information and forward packets toward the correct network.

Examples: IPv4, IPv6, ICMP, and routing protocols. ICMP supports control, error, and diagnostic messages, including the messages used by tools such as ping.

Security relevance: Network-layer threats include IP spoofing, route manipulation, unauthorized scanning, denial-of-service traffic, and poorly controlled movement between network segments. Firewalls, access control lists, segmentation, secure routing, monitoring, and filtering help defend this layer.

Important distinction: An IP address identifies a network location or interface at a particular time. It does not automatically prove the identity of a specific person because NAT, proxies, VPNs, shared networks, and compromised devices can affect the source address recorded by a system.

Memory clue: The Network layer decides where packets go between networks.

The Data Link layer moves data between devices on the same local network segment. It organizes network-layer packets into frames and uses local hardware addresses to deliver those frames.

MAC addresses are commonly used to identify network interfaces on a local network. Switches examine MAC addresses and forward frames through the appropriate switch port. Ethernet and Wi-Fi provide important Layer 2 technologies.

The Data Link layer also includes framing, local error detection, and rules for sharing a local communication medium. ARP helps IPv4 devices associate an IP address with a MAC address on a local network. IPv6 uses Neighbor Discovery for similar local-network functions.

Security relevance: Threats include ARP spoofing, MAC flooding, rogue devices, unauthorized wireless access points, VLAN attacks, and attacks that intercept or redirect local traffic. Switch security, port security, segmentation, 802.1X, wireless encryption, DHCP snooping, and dynamic ARP inspection can help protect the local network.

Memory clue: The Data Link layer moves frames across the local network using MAC addresses.

The Physical layer sends raw bits across a physical medium. It describes the electrical, optical, or radio signals used to represent binary data, along with connectors, cables, frequencies, signal timing, and transmission distances.

Examples: copper Ethernet cable, fiber-optic cable, Wi-Fi radio signals, network connectors, repeaters, hubs, antennas, and the electrical or optical signals that carry bits.

The Physical layer does not understand files, usernames, or IP addresses. It carries the physical signals that higher layers use to exchange those kinds of information.

Security relevance: Physical access can allow someone to disconnect equipment, install an unauthorized device, tap a cable, interfere with wireless signals, steal hardware, or cause a power outage. Locks, access controls, cable protection, surveillance, environmental controls, UPS devices, and secure equipment rooms help protect this layer.

Memory clue: The Physical layer carries bits as signals over a medium.

When a computer sends data, each layer adds information needed by the corresponding layer on the receiving computer. This wrapping process is called encapsulation.

Application data → Segment → Packet → Frame → Bits

At the Transport layer, application data is commonly divided into TCP segments or UDP datagrams. At the Network layer, the transport data is placed inside an IP packet. At the Data Link layer, the packet is placed inside a frame. At the Physical layer, the frame becomes bits represented by signals.

Network devices process different layers. A switch primarily works with Layer 2 frames, while a router primarily works with Layer 3 packets. The receiving computer removes the headers as data moves upward. This reverse process is called decapsulation.

Bits → Frame → Packet → Segment → Application data

Encapsulation allows each layer to focus on its own responsibility. A web browser does not need to know how a cable represents bits, and a network cable does not need to understand the meaning of a web request.

The OSI model is a useful seven-layer framework for learning and troubleshooting. Real-world Internet protocols are often described using the TCP/IP model, which groups some OSI layers together.

The models are not competing networks. They are ways of organizing related responsibilities. The OSI model gives more detail, while the TCP/IP model more closely reflects the protocols used by the Internet.

Layered thinking helps an analyst narrow down a problem instead of treating the entire network as one large mystery.

  • Physical: Is the device powered on? Is the cable connected? Is there signal or wireless coverage?
  • Data Link: Is the network interface connected? Is the device on the correct VLAN or Wi-Fi network? Are frames and MAC addresses working?
  • Network: Does the device have a valid IP address? Is the subnet, gateway, route, or firewall configuration correct?
  • Transport: Is the service listening on the expected port? Is TCP establishing a connection? Is UDP traffic being filtered?
  • Session: Is the login or application session active, expired, or being rejected?
  • Presentation: Can both sides interpret the data? Is encryption, encoding, or a certificate causing the problem?
  • Application: Is the service running correctly? Is the request valid? Are permissions, authentication, or application errors blocking the action?

A problem can involve more than one layer. For example, a web page that does not load could involve a disconnected cable, a missing IP address, a blocked TCP port, a failed DNS lookup, an expired TLS certificate, or an application error.

Follow one web request

When a user enters https://example.com, the application requests a web resource. DNS may resolve the domain name, TCP may establish a connection, TLS may protect the session, and HTTPS carries the request. IP addresses guide the packet between networks, frames move it across each local link, and physical signals carry the bits. The receiving computer reverses the process and delivers the response to the browser.

Layer checklist

Remember

OSI is a model for understanding communication. Real protocols may span more than one layer, but the model gives analysts a common language for explaining where a behavior or problem occurs.

Key takeaways

  • The OSI model has seven layers: Application, Presentation, Session, Transport, Network, Data Link, and Physical.
  • The Transport layer uses ports and protocols such as TCP and UDP to deliver data between applications.
  • The Network layer uses IP addressing and routing to move packets between networks.
  • The Data Link and Physical layers handle local frames, hardware addresses, and signals.
  • Encapsulation wraps data as it moves down the sender's stack; decapsulation unwraps it at the receiver.
  • Layered thinking helps security teams understand attacks and troubleshoot communication.
