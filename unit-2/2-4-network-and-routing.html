2.4 • Network and Routing

Network and Routing

Before learning about specific network protocols, it is important to understand how devices identify one another and communicate across a network. This section explains how IP addresses, routing, and common protocols work together to move traffic safely and efficiently.

Big idea

Devices need addresses, routes, and protocol rules.

When a computer wants to communicate with another device, it needs to know where that device is on the network. That is where an IP address becomes important. An IP address helps identify the source and destination of network traffic, and routers then help deliver packets across the network.

Addressing

IP addresses

Every packet includes sender and recipient location information so network devices know where the traffic came from and where it needs to go.

Routing

Packet delivery

Routers inspect the destination and move the data toward the correct network while using TTL and routing information to avoid loops.

Protocols

Core services

Protocols such as DHCP, DNS, ICMP, RIP, NTP, SSH, SCP, and TLS provide automatic configuration, addressing, timing, diagnostics, and secure communication.

IP addresses

IP stands for Internet Protocol. The Internet Protocol is responsible for addressing and routing packets between networks. When information is sent across a network, it is broken into smaller pieces called packets. Each packet contains information that helps networking devices determine where it came from and where it should go.

An IP address helps provide two key pieces of information:

  • Source IP address = the address of the device that sent the packet.
  • Destination IP address = the address of the device that should receive the packet.

Example:

Source: 192.168.1.25
Destination: 142.250.72.14

Think of an IP address like a mailing address. Your device is like a house, the IP address is the house's address, the network is the neighborhood, the router is the system that helps move the mail between neighborhoods, and a data packet is the piece of mail. An IP address does not necessarily identify a specific person or physical device forever, because addresses can change, especially when they are assigned dynamically.

IPv4 is the older and still extremely common version of the Internet Protocol. It uses 32-bit addresses. Because computers represent information in binary, an IPv4 address can be thought of as a group of 32 binary digits.

These 32 bits are divided into four groups of 8 bits, called octets. Example:

192.168.1.25

192 . 168 . 1 . 25
8 bits + 8 bits + 8 bits + 8 bits = 32 bits

Each octet can have a value from 0–255. That is why an IPv4 address can look like:

  • 10.0.0.15
  • 192.168.1.25
  • 172.16.4.100
  • 8.8.8.8

Example in binary:

192.168.1.25 = 11000000.10101000.00000001.00011001

IPv4 has 2³² possible addresses, which is approximately 4.3 billion addresses. That sounds like a huge number, but the Internet has billions of devices, and many devices need multiple addresses over time, which helped lead to the creation of IPv6.

IPv4 packet header

This diagram shows the IPv4 header structure, including version, source address, destination address, and TTL.

IPv4 packets contain a header that provides information needed to deliver and process the packet. Some important fields include:

  • Version — identifies which version of IP is being used. For IPv4, the value is 0100, which is binary for 4.
  • Internet Header Length (IHL) — tells the receiving device how long the IPv4 header is. The field is 4 bits long.
  • Source Address — contains the IPv4 address of the device that sent the packet.
  • Destination Address — contains the IPv4 address of the intended recipient.
  • Time to Live (TTL) — prevents packets from traveling forever. Each router decreases the value. If TTL becomes zero, the packet is discarded.

This helps protect networks from routing loops.

IPv6, or Internet Protocol version 6, was developed to address major limitations of IPv4, especially the limited number of available IPv4 addresses. IPv6 uses 128-bit addresses instead of IPv4's 32-bit addresses.

That creates an enormous number of possible addresses:

2¹²⁸ possible addresses, which is about 340 undecillion addresses.

Unlike IPv4, IPv6 does not use four decimal numbers separated by periods. Instead, it uses eight groups of hexadecimal numbers separated by colons. Example:

2001:0db8:85a3:0000:0000:8a2e:0370:7334

Each group contains 4 hexadecimal digits, and each hexadecimal digit represents 4 bits.

8 groups × 16 bits = 128 bits

IPv6 addresses can be shortened. For example:

2001:0db8:85a3:0000:0000:8a2e:0370:7334 can be written as 2001:db8:85a3::8a2e:370:7334.

Leading zeros can be removed, and consecutive groups containing only zeros can be represented using ::. Important: :: can only be used once in an IPv6 address.

Remember: IPv4 = 32 bits, IPv6 = 128 bits.

Simple memory trick: IPv6 has a much larger address space than IPv4.

DHCP stands for Dynamic Host Configuration Protocol. It automatically provides devices with network configuration information when they join a network. Instead of manually configuring every computer with an IP address, a DHCP server can assign that information automatically.

A DHCP server can provide information such as:

  • IP address
  • Subnet mask
  • Default gateway
  • DNS server information
  • Lease time, which tells how long the address can be used

DHCP uses UDP port 67 for the server and UDP port 68 for the client. When a device connects to Wi-Fi, it requests configuration, the DHCP server responds, and the device receives its IP address and other settings.

Security issue: a rogue DHCP server is an unauthorized server that gives incorrect network settings. An attacker could try to provide a victim with a malicious default gateway, malicious DNS server, or incorrect IP configuration. This could redirect traffic or interfere with communication.

DHCP snooping is a security feature used to help defend against rogue DHCP servers. A switch can distinguish between trusted ports and untrusted ports. Trusted ports are where legitimate DHCP servers are expected; untrusted ports are where clients are connected. The switch blocks DHCP responses coming from unauthorized ports.

Important distinction: Rogue DHCP server = attack/threat and DHCP snooping = defense against rogue DHCP activity.

ARP stands for Address Resolution Protocol. It helps a device match an IP address to a MAC address on the same local network.

When your computer wants to send data to another device on the same LAN, it usually knows the destination IP address but not the destination MAC address. ARP helps solve that problem by asking, “Who has this IP address?” and the device with that IP responds with its MAC address.

Think of it like this: the IP address is the street address, but the MAC address is the actual hardware identifier for the device on the local network. ARP connects those two layers so the packet can be delivered correctly.

ARP is especially important on local networks because it helps devices communicate before traffic leaves the network segment.

Quick memory trick: ARP = IP to MAC on the LAN.

DNS stands for Domain Name System. DNS translates human-readable domain names into IP addresses. People generally prefer to type example.com rather than remember an IP address like 93.184.216.34.

Think of DNS like the Internet’s phone book:

Domain name → IP address
example.com → 93.184.216.34

DNS normally uses port 53. It commonly uses UDP port 53 for regular queries, while TCP port 53 is used for specific DNS operations. When you enter a website address into your browser, your device usually performs a DNS lookup to find the correct IP address before connecting.

Because DNS directs users to websites and other services, attackers may manipulate DNS information. This can be used in DNS spoofing or DNS cache poisoning, where the user is sent to a malicious or fraudulent website instead of the legitimate destination.

Remember: DNS = Domain Name System; main job = translate domain names into IP addresses; port = 53.

ICMP stands for Internet Control Message Protocol. ICMP is used by network devices to send control, diagnostic, and error messages. Unlike TCP and UDP, ICMP does not use a port number. Instead, it is identified by IP protocol number 1.

One familiar use of ICMP is ping. When you ping another device, your computer sends an ICMP Echo Request to determine whether the destination can be reached and whether it responds. Ping can help determine whether a device is reachable, how long the response takes, and whether packets are being lost.

RIP stands for Routing Information Protocol. RIP is a routing protocol that helps routers determine paths through a network. It uses the number of hops as a metric. A hop is a router that a packet passes through. RIP has a maximum hop count of 15, and a route with a metric of 16 is considered unreachable. This limits routing loops. RIP uses UDP port 520.

NTP stands for Network Time Protocol. NTP is used to synchronize the clocks of computers and network devices. It uses UDP port 123. Accurate time is essential for logs, authentication, certificates, and troubleshooting, because if system clocks are out of sync it can be hard to determine the order of events in an attack.

SSH stands for Secure Shell. SSH provides a secure way to remotely connect to another computer or network device. SSH encrypts the communication between the two systems. This makes it useful for remotely administering servers, routers, switches, Linux computers, and other network-connected systems. SSH normally uses TCP port 22.

SCP stands for Secure Copy Protocol. SCP is used to securely transfer files between systems. SCP operates using SSH, which provides the secure connection. This means the file transfer is protected while it travels across the network. Like SSH, SCP commonly uses TCP port 22.

A simple memory rule:

  • SSH → remotely connect to a computer
  • SCP → securely copy files between computers

Both commonly use TCP port 22.

TLS stands for Transport Layer Security. TLS is a cryptographic protocol designed to protect data while it travels across a network. It can provide encryption, authentication, and integrity. Encryption helps prevent others from reading the data, authentication helps verify the identity of the server, and integrity helps detect whether data changed during transmission.

TLS is commonly used to protect web traffic. When you visit a website using HTTPS, TLS is generally used to protect the connection. HTTPS commonly uses TCP port 443, but it is more accurate to remember that TCP 443 = HTTPS, which commonly uses TLS.

Important: TLS itself does not have a single dedicated port. It is a protocol used by different services, including HTTPS, and can be used by other protocols and applications as well.

Important ports and protocols to remember

  • DHCP = Dynamic Host Configuration Protocol; UDP 67 server / 68 client
  • DNS = Domain Name System; UDP/TCP 53
  • ICMP = Internet Control Message Protocol; IP protocol 1
  • RIP = Routing Information Protocol; UDP 520
  • NTP = Network Time Protocol; UDP 123
  • SSH = Secure Shell; TCP 22
  • SCP = Secure Copy Protocol; TCP 22
  • HTTPS = Hypertext Transfer Protocol Secure; TCP 443
  • TLS = Transport Layer Security; no single dedicated port

My notes

Quick memory guide

  • IP → identifies where network traffic is going
  • DHCP → gives devices network configuration
  • DNS → domain name → IP address
  • ICMP → errors, control, and tools like ping
  • RIP → helps routers determine routes
  • NTP → keeps clocks synchronized
  • SSH → securely access another computer
  • SCP → securely copy files using SSH
  • TLS → protects data while it travels

Key things to remember

  • IPv4 uses 32-bit addresses.
  • IPv6 uses 128-bit addresses.
  • DHCP automatically assigns network configuration information.
  • DNS translates domain names into IP addresses.
  • ICMP does not use TCP/UDP ports; it uses protocol number 1.
  • RIP uses UDP 520 and has a maximum usable hop count of 15.
  • NTP uses UDP 123 to synchronize time.
  • SSH uses TCP 22 for secure remote access.
  • SCP uses SSH and normally uses TCP 22 for secure file transfer.
  • HTTPS commonly uses TCP 443 and can use TLS to secure the connection.
  • TLS is a security protocol, not a single port number.

Key takeaways

  • IPv4 uses decimal numbers and periods; IPv6 uses hexadecimal and colons.
  • DHCP helps devices automatically join a network without manual setup.
  • DNS turns names like example.com into IP addresses that devices can use.
  • ICMP, RIP, and NTP each support different network management functions.
  • SSH, SCP, and TLS are essential for secure administration, file transfer, and encrypted communication.
