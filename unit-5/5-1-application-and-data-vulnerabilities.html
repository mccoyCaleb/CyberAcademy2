5.1 • Application and Data Vulnerabilities and Attacks

Application and Data Vulnerabilities

A vulnerability is a weakness in a system, application, configuration, or process that can potentially be exploited. Attackers may exploit a vulnerability to read information, modify data, delete data, execute unauthorized commands, gain additional privileges, disrupt an application, or take control of part of a system.

Big idea

Vulnerabilities are weaknesses; attacks are attempts to exploit them.

An attack is not the same thing as a vulnerability. A vulnerability is the flaw that exists. An attack is the attempt to turn that flaw into harm.

Imagine a website allows users to enter information into a search box. If the application does not properly handle the input, an attacker might be able to enter specially constructed data that causes the application to behave in an unintended way.

Key concepts from the notes

A vulnerability is a weakness in a system, application, configuration, or process that can potentially be exploited.

An attacker may exploit a vulnerability to:

  • Read information they should not have access to.
  • Modify data.
  • Delete data.
  • Execute unauthorized commands.
  • Gain additional privileges.
  • Disrupt an application.
  • Take control of part of a system.

Data can be vulnerable depending on where it is stored and how it is protected.

Unencrypted data is especially risky. If sensitive information is stored without encryption, someone who gains access to the storage system may be able to read it directly.

Username: alex
Password: MyPassword123
SSN: 123-45-6789

If this information is stored as readable text, any unauthorized user with access to the file may be able to read it.

Applications commonly run using a particular user's permissions.

If an application is compromised, the attacker may inherit some of those permissions.

A user may have permission to read /student-files/ but not /admin-files/. If the application runs with the user's permissions and is compromised, the attacker may be able to access the student files, but not automatically the administrator files.

This is one reason least privilege is important: give users and applications only the permissions they need.

Applications can contain vulnerabilities because of:

  • Programming errors.
  • Poor input validation.
  • Incorrect permissions.
  • Unsafe assumptions.
  • Improper handling of data.
  • Insecure configurations.

The AP framework specifically identifies several important application attacks:

  • SQL injection
  • Cross-site scripting (XSS)
  • Buffer overflow
  • Buffer overread
  • Directory traversal

SQL injection is an attack in which an attacker provides specially constructed input that causes an application to modify or interfere with a SQL query.

Example: SELECT * FROM students WHERE username = 'alex';

If the application directly inserts untrusted user data into a SQL query without properly validating or safely handling it, an attacker may be able to alter the intended query.

Depending on the vulnerability and permissions available, SQL injection may allow an attacker to retrieve unauthorized information, modify database records, delete information, or bypass intended restrictions.

Defense: use parameterized queries or prepared statements instead of directly concatenating untrusted input into a SQL command.

Cross-site scripting occurs when an attacker causes a website to deliver malicious script content to a user's browser.

The problem occurs when an application treats untrusted input as trustworthy webpage code.

Potential consequences include manipulating webpage content, performing actions as the victim within a website, stealing sensitive information accessible to the script, or tricking users into interacting with malicious content.

Defense: properly validate and sanitize/escape untrusted input before displaying it, and use security controls such as a Content Security Policy where applicable.

A buffer is a region of memory used to temporarily hold data.

A buffer overflow occurs when a program attempts to place more data into a buffer than the allocated space can hold.

In software, this can cause application crashes, corrupted data, unexpected behavior, or potential execution of unauthorized code in vulnerable systems.

Defense: bounds checking, safe memory-management practices, memory-safe programming languages, and compiler and operating system protections.

A buffer overread occurs when a program reads beyond the intended boundaries of a buffer.

Instead of writing too much data into memory, the program attempts to read data it should not be reading.

This could potentially expose information stored nearby in memory.

Buffer overflow = writes too much data into a buffer.
Buffer overread = reads beyond the intended end of a buffer.

Directory traversal is an attack in which an attacker manipulates a file path to access files outside the directory the application intended to expose.

If the application improperly handles file paths, an attacker may attempt to manipulate the path to move outside the intended directory.

Conceptually: /public/file.txt becomes /public/../private/file.txt.

Successful directory traversal could expose configuration files, application data, credentials, source code, or other sensitive files.

Not every vulnerability creates the same amount of danger.

When evaluating a vulnerability, consider:

  • What information could be exposed?
  • How likely is exploitation?
  • What could happen if it is exploited?

Possible impacts include data theft, data modification, data deletion, service disruption, loss of confidentiality, loss of integrity, and loss of availability.

Quick memory check

Which attack is most closely tied to untrusted input being treated as webpage code? What about a path like /public/../private/file.txt?

Key terms

  • Vulnerability = weakness that could be exploited.
  • Attack = the exploit attempt.
  • SQL injection = modifies a SQL query.
  • XSS = malicious script runs in a user's browser.
  • Buffer overflow = writes beyond allocated memory.
  • Directory traversal = escapes the intended file directory.

Think like a defender

Every application should treat input as untrusted. If the application accepts a username, password, search query, file name, or form submission, it should validate that input before processing it.

My notes

Key takeaways

  • A vulnerability is a weakness; an attack is the attempt to exploit it.
  • Applications can be vulnerable because of poor input validation, unsafe code, misconfigured permissions, or insecure assumptions.
  • SQL injection, XSS, buffer overflow, buffer overread, and directory traversal are all examples of application attacks.
  • Risk depends on what data could be exposed, how likely exploitation is, and what impact would result.
