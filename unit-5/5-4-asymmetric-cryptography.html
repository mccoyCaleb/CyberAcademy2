5.4 • Asymmetric Cryptography

Public and Private Keys

Symmetric encryption requires both parties to possess the same secret key. Asymmetric cryptography addresses this challenge by using a mathematically related pair of keys: a public key and a private key.

Big idea

The public key can be shared; the private key must stay secret.

Asymmetric cryptography uses a pair of mathematically related keys. The public key can be shared with others. The private key must be kept secret. If an attacker obtains someone's private key, the security of systems relying on that key can be compromised.

Symmetric encryption requires both parties to possess the same secret key. That creates a problem: how can two people securely exchange the secret key if they do not already have a secure communication channel?

Asymmetric cryptography helps address this problem.

Asymmetric cryptography uses a pair of mathematically related keys:

  • Public key — can be distributed.
  • Private key — must be protected and never exposed.

The keys are related, but they have different roles.

Suppose Alice wants to send Bob a secret message. Bob has a public key and a private key. Alice obtains Bob's public key and encrypts the message using Bob's public key.

Bob then decrypts it using his private key.

Public key encrypts; corresponding private key decrypts.

This allows someone to send encrypted information without first sharing a secret symmetric key.

Asymmetric cryptography can also be used in the opposite direction to help provide authentication and integrity.

A sender can use their private key to create a digital signature. Others can use the sender's public key to verify it.

Message → Hash → Signature created using private key

A recipient can use the public key to verify that the message came from the expected key holder and that it was not changed.

Important distinction: encryption primarily addresses confidentiality, while digital signatures primarily help with authentication and integrity.

Public key infrastructure (PKI) is the system used to bind a public key to a real-world identity. This is usually done through a digital certificate, which is issued by a trusted certificate authority (CA).

When a browser connects to a website over HTTPS, it often checks whether the server's certificate is signed by a trusted CA. If the certificate is valid and trusted, the browser can have confidence that the public key belongs to the expected website.

This matters because public keys are only useful if the party using them can trust that the key belongs to the correct person or service. Without that trust model, someone could claim to be a fake website and share a different public key.

The AP framework emphasizes that key length affects the security of encrypted data. Longer keys generally create a larger keyspace, making brute-force key searching more difficult, although security also depends on the algorithm and implementation.

For example, 2^8 possible keys is much smaller than 2^256 possible keys.

But longer is not automatically better because longer keys can require more computation, processing time, and resources.

The AP framework identifies RSA and ECC as examples of asymmetric algorithms.

RSA is a widely known public-key cryptographic system based on mathematical properties involving very large numbers.

ECC (Elliptic Curve Cryptography) provides public-key cryptography using elliptic-curve mathematics. One advantage is that ECC can provide strong security with comparatively smaller key sizes than some traditional public-key systems.

Modern systems often combine both approaches. Asymmetric cryptography can help establish or exchange a secret, and symmetric cryptography can then efficiently protect large amounts of data.

Public keys solve the key-exchange problem, but they do not automatically prove that a key belongs to a trusted party. A certificate authority (CA) and a chain of trust help solve that problem.

This is why browsers and operating systems often warn when a certificate is expired, self-signed, or issued by an untrusted source. Security systems do not just trust “any public key”; they trust keys that are verified through a trusted authority or a known chain of trust.

In short: cryptography gives keys power, and trust models decide which keys to trust.

Key idea

  • Public key = share it
  • Private key = protect it
  • Digital signature = proves origin and integrity
  • RSA / ECC = common asymmetric algorithms

Why it matters

Asymmetric cryptography solves the key-exchange problem. It is often used to establish trust and exchange secrets, while symmetric encryption then handles the bulk of data protection efficiently.

My notes

Key takeaways

  • Asymmetric cryptography uses a public/private key pair rather than one shared secret.
  • The public key can be shared; the private key must stay protected.
  • Public-key encryption protects confidentiality without first exchanging a shared secret.
  • Digital signatures help provide authentication and integrity.
  • Modern systems often use both symmetric and asymmetric cryptography together.
