5.3 • Protecting Stored Data with Cryptography

Cryptography and Encryption

Cryptography is the use of mathematical techniques to protect information. It provides confidentiality, integrity, authentication, and nonrepudiation. In this topic, the AP framework focuses on how algorithms and keys transform information.

Big idea

Encryption protects data; hashing verifies data without recovering the original input.

Reversible

Plaintext is transformed to ciphertext using a key, then recovered using the correct key.

Hashing

One-way

Input produces a fixed-size digest. It is used to verify integrity, not recover the original text.

Symmetric

Shared key

Same key used to encrypt and decrypt, often for large data sets.

Encryption transforms readable information into an unintelligible form using an encryption algorithm and a key.

The original readable information is called plaintext. The encrypted information is called ciphertext.

Plaintext → Encryption algorithm + key → Ciphertext
Ciphertext → Decryption algorithm + key → Plaintext

Suppose the plaintext is MEET AT 5, and after encryption it becomes something like X7Q9K2L....

Encryption is designed to be reversible. The goal is to protect information while still allowing an authorized party to recover the original information.

Hashing is designed to be one-way. A hash is not intended to be decrypted back into the original input.

Encryption protects data by making it unreadable and allowing authorized recovery.
Hashing creates a digest that can be used to verify data or passwords without storing the original input.

A cryptographic hash function takes input and produces a fixed-size output called a hash, hash value, or digest.

For example, "Hello" might become 2cf24dba....

Changing the input even slightly should produce a substantially different hash. For example, "Hello" and "hello" should produce different outputs.

Hashing can help detect whether data has changed.

Suppose a file originally produces HASH A. Later, someone calculates the hash again. If the result is HASH B and HASH A ≠ HASH B, then the data has changed.

This can help detect accidental or malicious modification.

Passwords should not normally be stored as plaintext.

User password → Password hashing function → Stored password hash

When the user logs in, the system processes the submitted password and checks it against the stored password-verification data.

For password storage, specialized password-hashing algorithms are used rather than relying on a fast general-purpose hash alone.

A salt is a random value added to a password before hashing.

Password + Salt → Hash function → Password hash

Suppose two users both choose password123. Without salts, they could potentially produce the same hash. With unique salts, the resulting hashes are different.

Salting makes precomputed password-hash tables much less useful.

Symmetric encryption uses the same key for encryption and decryption.

Plaintext → Encryption → Ciphertext
Sender and receiver both know the secret key.

Advantages: symmetric encryption is generally fast, efficient, and suitable for encrypting large amounts of data.

Disadvantage: the major challenge is key distribution. If an attacker obtains the key, they may be able to decrypt the protected data.

One major symmetric encryption algorithm is AES — Advanced Encryption Standard.

AES uses block-based encryption. Common AES key sizes include 128-bit, 192-bit, and 256-bit keys.

The key size affects the number of possible keys and the computational difficulty of guessing the key through brute force.

A 128-bit key has 2^128 possible combinations, and a 256-bit key has 2^256 possible combinations.

A block cipher processes data in fixed-size blocks.

Large message → [Block 1][Block 2][Block 3][Block 4] → Encryption → [Cipher][Cipher][Cipher][Cipher]

AES is a block cipher. The AP framework contrasts this with stream encryption, which processes information as a continuous stream of data.

Memory guide

  • Encryption = reversible
  • Hashing = one-way
  • Salt = random value added before hashing
  • Symmetric = same key for encrypt and decrypt
  • AES = common symmetric algorithm

Why it matters

Modern systems often use encryption to protect stored data and hashing to protect passwords and verify integrity. The difference between these two operations is critical in cybersecurity.

My notes

Key takeaways

  • Encryption protects confidentiality and allows authorized recovery.
  • Hashing verifies integrity and protects passwords without storing plaintext.
  • Salts prevent identical passwords from producing the same stored hash.
  • Symmetric encryption uses the same key for both encryption and decryption.
  • AES is a major symmetric encryption standard.
