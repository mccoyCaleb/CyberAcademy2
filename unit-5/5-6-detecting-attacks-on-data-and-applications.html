5.6 • Detecting Attacks on Data and Applications

Monitoring and Detection

Preventing attacks is only part of cybersecurity. Organizations also need to determine when something suspicious has occurred. Logs, monitoring, and integrity checks help reveal abnormal access and changes.

Big idea

Monitoring data access and file integrity can reveal suspicious behavior before damage spreads.

Organizations can monitor who accessed information, when it was accessed, what information was accessed, where the access originated, and what actions were performed.

Access

Who and when

Logs can show which accounts are interacting with data and when.

Trap

Honeypot

A fake system used to attract and detect unauthorized activity.

Integrity

Hash check

Detects whether a file or asset has changed.

Organizations can monitor:

  • Who accessed information.
  • When it was accessed.
  • What information was accessed.
  • Where the access originated.
  • What actions were performed.

For example, if an employee normally accesses company documents during 8:00 AM–5:00 PM from the company network and logs suddenly show access at 2:13 AM from an unusual location, that activity may deserve investigation.

A honeypot is a system or resource designed to attract or detect attackers.

It is intentionally made to appear interesting to an attacker.

Because legitimate users generally should not interact with it, activity on the honeypot can be a strong indicator of suspicious behavior.

A company creates a fake database server containing fake information. An attacker discovers it and begins attempting to access it. The security team receives an alert because legitimate employees were not supposed to use the fake server.

A honeytoken is a piece of information or resource designed to detect unauthorized access.

Examples could include fake credentials, fake database records, fake files, or special tracking information.

If someone uses a honeytoken, the organization can investigate the activity.

A cryptographic hash can be used to detect whether a file has changed.

Suppose an organization calculates the hash of an original file. Later, the organization calculates the hash again. If the values differ, the file has changed.

This does not automatically tell us who changed it or why it changed, but it tells us that the file's contents are different.

The AP framework gives examples of suspicious activity that can appear in logs, including:

  • Unexpected access at unusual times
  • Large numbers of files accessed
  • Mass changes to application or data files
  • Access from unusual locations or devices
  • Failed login attempts or privilege escalation attempts

Logs help detect suspicious behavior because activity that deviates from expected patterns may indicate an attack or misuse.

Detection tools

  • Monitoring = watch who, when, what, where, and how.
  • Honeypot = decoy system to attract attackers.
  • Honeytoken = fake secret or record used to detect misuse.
  • File integrity monitoring = hash changes to detect tampering.

Detection rule

Suspicious activity does not automatically prove an attack occurred, but it may be worth investigating. Logs are one of the best ways to turn a signal into an action.

My notes

Key takeaways

  • Monitoring helps reveal who accessed what, when, and from where.
  • Honeypots and honeytokens are designed to attract and detect attacker behavior.
  • File integrity monitoring can detect unauthorized file changes using hash comparisons.
  • Logs are a key tool for identifying suspicious patterns and investigating attacks.
