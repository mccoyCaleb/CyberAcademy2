5.2 • Protecting Applications and Data

Managerial Controls and Access Controls

Protecting data is not just a technical problem. Organizations also need policies, procedures, classifications, and access-control systems. Security depends on data state, who can access what, and how access is limited.

Big idea

Different data states require different controls.

One of the most important concepts in cybersecurity is understanding that data exists in different states. Data at rest is stored data. Data in transit is moving between systems. Data in use is currently being processed or accessed.

Think: At rest = stored, In transit = moving, In use = being processed.

At rest

Stored

Files, databases, backups, USB drives, and other stored data.

In transit

Moving

Data sent over a network or between systems.

In use

Processing

Data currently being accessed, displayed, or modified.

Data exists in different states. The most important are:

  • Data at rest — stored data that is not currently being transmitted.
  • Data in transit — data moving between systems.
  • Data in use — data currently being processed or accessed by a system.

The controls needed for each state differ. A database on a server needs different controls than information being sent over a network.

Organizations often classify data according to how sensitive it is.

Classification helps determine who should have access, how data should be stored, how transmitted, how monitored, and what security controls should be applied.

  • Public — freely shared.
  • Internal — intended primarily for members of an organization.
  • Confidential — only for authorized individuals.
  • Highly sensitive — unauthorized disclosure could cause serious harm.

PII is information that can identify or help identify an individual.

Examples include a name, address, email address, phone number, Social Security number, biometrics, or other identifying information.

If PII is exposed, attackers may be able to use it for identity theft, fraud, social engineering, account takeover, or tracking.

Protected Health Information refers to protected health-related information associated with an individual.

The AP framework identifies HIPAA as the regulation related to protected health information.

Examples include medical records, diagnoses, treatment information, and certain information connected to healthcare services.

Payment information can require special protection.

Examples include credit card numbers, debit card information, cardholder information, and other payment-related data.

The AP framework identifies PCI DSS as a standard governing protection of payment card information.

Organizations should establish policies describing how cryptography is used.

A cryptography policy may specify approved encryption algorithms, minimum key lengths, requirements for encryption, key-generation requirements, key-storage requirements, and when encryption is required.

This is important because simply saying “use encryption” is not enough. The organization must determine how encryption is implemented.

Access control determines what users or systems are allowed to do with resources.

The basic idea is: Who can do what to which resource?

Access control can determine whether a user can read data, write data, modify data, delete data, execute programs, or access specific resources.

RBAC assigns permissions based on a user's role.

Student → Read assignments
Teacher → Read/write assignments
Administrator → Manage users and settings

Instead of assigning every permission individually, administrators assign users to roles. A user assigned to a role automatically receives those permissions.

RuBAC determines whether access is allowed based on rules.

A rule might consider the user, location, time, device, network, or other conditions.

Allow access IF user = teacher AND time = school hours

If the conditions are not satisfied, access may be denied.

DAC allows the owner of a resource to determine who can access it.

For example, a user creates a file and decides which other users can read or modify it.

The owner has discretion over access.

MAC uses centrally defined security rules and classifications.

Users cannot simply change permissions because they own a file. Access can depend on security clearance, data classification, and centrally established security policies.

MAC is commonly associated with environments requiring strict centralized control.

Least privilege means giving a user or program only the permissions necessary to perform its required tasks.

A student who only needs to read a file should not automatically receive permission to read, write, delete, or change permissions. Instead, they might receive: Read.

Least privilege limits the damage caused if an account or application is compromised.

Control types

  • RBAC → permissions by role
  • RuBAC → permissions by rules and conditions
  • DAC → resource owner decides access
  • MAC → centralized policy decides access
  • Least privilege → minimal permissions only

Why it matters

Organizations need to decide what information they collect, why they collect it, who can access it, and how it is protected. The same data may require different controls depending on whether it is stored, moving, or being processed.

My notes

Key takeaways

  • Data exists at rest, in transit, and in use.
  • Data classification determines how sensitive information is handled.
  • PII, PHI, and payment data all require special protection.
  • Access control models include RBAC, RuBAC, DAC, and MAC.
  • Least privilege reduces the damage from compromised accounts and applications.
