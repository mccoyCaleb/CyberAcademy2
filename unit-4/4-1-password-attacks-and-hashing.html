4.1 • Password attacks and hashing

Password Attacks and Hashing

Passwords remain one of the most common ways people prove who they are, but they are also one of the most common weak points in security. Attackers use brute-force, dictionaries, credential stuffing, and password spraying to try to guess or reuse passwords.

Big idea

One weak password can affect many services.

Password reuse is dangerous because a breach in one service can put other accounts at risk. Credential stuffing uses exposed username-password pairs to try other sites, which is why unique passwords and MFA matter.

Common password attacks

Brute force means trying many possible passwords until one works. Attackers often use automated software to generate combinations quickly.

A short numeric password is especially vulnerable because there are fewer possibilities. The longer and less predictable the password, the harder it is to guess.

A dictionary attack uses common words, names, and phrases instead of randomly testing every possibility. Attackers often test patterns like:

  • password
  • admin123
  • summer2025
  • schoolname1

Many people choose predictable passwords, so a prepared list can be surprisingly effective.

Credential stuffing uses password and username pairs stolen in one breach to try other services. This is why password reuse is so dangerous.

If an exposed email and password are tried on a bank, school, or social media account, the attacker may gain access to more than one account.

Password spraying means trying a small number of common passwords across many accounts instead of trying many passwords against one account. This method may avoid some simple account-level protections.

For example, an attacker might test a few common passwords against many employee accounts.

A rainbow-table attack uses precomputed tables that map possible passwords to their hash values. If a system stores weak password hashes, the attacker may be able to look up original passwords faster.

That is why using a strong password-hashing algorithm with salts is so important. Different salts make rainbow tables much less useful.

Password hashing

Key idea

Hashing is meant to be one-way.

Systems should not store passwords as readable plaintext. Instead, they store a password hash created by a suitable password-hashing algorithm, such as Argon2id, scrypt, or bcrypt.

Important properties of a password hash:

  • One-way: The original password is difficult to recover from the hash.
  • Fixed-length output: Hashes have a defined size.
  • Sensitive to input: A small change in the password changes the hash.
  • Collision risk still exists theoretically: cryptographic hashes are designed to make collisions difficult.

Important: A hash is not encryption. Encryption allows authorized decryption with a key; a secure password hash is designed to be difficult to reverse.

Salt

A salt is a random value added before hashing. It makes identical passwords produce different hashes across accounts, which helps defend against precomputed attacks.

For password storage, systems should use hashing algorithms designed specifically for passwords, not ordinary fast hashes alone.

Checklist

Remember

  • Unique passwords matter more than complexity alone.
  • One exposed password can affect many accounts.
  • Salted password hashes help prevent rainbow-table attacks.
  • MFA reduces the impact of password compromise.
