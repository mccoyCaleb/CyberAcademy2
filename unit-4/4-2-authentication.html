4.2 • Authentication

Authentication

Authentication verifies identity. A system needs to determine whether a person or device is really who it claims to be before granting access.

ProgressIdentity verification
Overview 4.1 4.2 4.3 4.4
Big idea

Authentication is not the same as authorization.

Authentication answers, “Who are you?” while authorization answers, “What are you allowed to do?” A user may prove their identity and still lack permission to access certain files or systems.

The four authentication factors

Knowledge factor includes passwords, PINs, and answers to security questions.

These are useful, but weak if reused, guessed, or exposed in a breach. A PIN and a password are both knowledge factors; using two of them does not automatically create MFA.

Possession factor uses an item the user physically has, such as a security key, smartphone, or hardware token.

This adds protection because the attacker must have both the password and the device or token.

Biometric factor uses fingerprint, face, iris, or voice data. These are physical or behavioral characteristics that can be measured and compared to enrolled data.

Biometrics are useful, but they are not perfect and can sometimes produce false matches or false negatives.

Location factor uses where the user is signing in from, such as an approved office network or a trusted region.

Location is helpful as supporting evidence, but it can be inaccurate or manipulated, so it is often used as part of a risk-based decision rather than a sole factor.

Multi-factor authentication

What MFA means

MFA requires at least two different factor categories. For example:

  • Password + security key = knowledge + possession
  • Password + fingerprint = knowledge + biometric
  • Security key + fingerprint = possession + biometric

This matters because if one factor is stolen or guessed, the attacker still needs the second one. MFA does not eliminate all risk, but it significantly reduces the chance of a single stolen password providing access.

Passwordless

Authentication without a password

Some systems use passwordless authentication, such as passkeys or hardware security keys. These often rely on public-key cryptography: the device proves possession of a private key, and the service verifies it using the corresponding public key.

Passwordless methods can reduce the risk of password guessing and phishing, depending on how the system is implemented.

Checklist

Remember

  • Authentication proves identity.
  • Authorization decides what the identity is allowed to do.
  • MFA uses different factor categories, not just multiple passwords.
  • Strong authentication is crucial for sensitive accounts.
