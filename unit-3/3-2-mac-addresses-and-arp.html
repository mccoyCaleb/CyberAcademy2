3.2 • MAC Addresses and ARP Review

MAC Addresses and ARP

Before studying network defenses, review how devices identify one another on a local network. IP addresses help locate devices across networks, while MAC addresses and ARP help deliver traffic across the local network segment.

Big idea

IP addresses locate; MAC addresses deliver locally.

An IP address identifies a device or network interface on an IP network and helps route traffic toward a destination. A MAC address is associated with a network interface and is used for communication on a local network. ARP helps connect these two pieces of information.

IP address → local ARP lookup → MAC address → Ethernet frame

Reviewing MAC addresses and ARP

A MAC address is an address associated with a network interface. A computer, phone, printer, or access point may have a MAC address for each network interface it uses.

MAC addresses are used for communication on a local network. A switch can use MAC-address information to determine which port leads toward a device and forward Ethernet frames to the correct location.

MAC addresses are not a perfect form of authentication. An attacker may be able to change the MAC address their device presents to the network. This is called MAC spoofing.

MAC address = local network interface identity, not guaranteed proof of a person or device.

An IP address helps with communication at the network layer. It identifies a logical network location and can change when a device joins a different network or receives a different assignment.

A MAC address is used for local network delivery and is associated with a network interface. It is used inside the local network segment, while IP addressing helps traffic travel between networks.

These addresses work together. A packet can use IP addresses for its network-layer source and destination, while the frame carrying it uses MAC addresses for the current local link.

ARP stands for Address Resolution Protocol. Computers on a local network often need to know both the destination IP address and the destination MAC address.

Suppose Computer A knows that Computer B has IP address 192.168.1.20, but Computer A needs the MAC address associated with that IP address to communicate locally. ARP helps answer:

“Which MAC address belongs to 192.168.1.20?”

The computer can store this information in an ARP table or ARP cache. When the mapping is known, the device can place the destination MAC address into the local Ethernet frame.

ARP is used on the local network. If the destination is outside the local network, the device generally resolves the MAC address of its default gateway and sends the frame to that gateway. The router then forwards the packet toward the remote network.

A simplified ARP process looks like this:

  1. Computer A wants to send local traffic to IP address 192.168.1.20.
  2. Computer A checks its ARP cache for a matching IP-to-MAC entry.
  3. If there is no entry, Computer A sends an ARP request asking which device has that IP address.
  4. The device using 192.168.1.20 sends an ARP reply containing its MAC address.
  5. Computer A stores the mapping temporarily and sends the local frame to that MAC address.
Known IP → ARP request → ARP reply → MAC mapping → local frame

ARP requests may be broadcast across the local network because the sender does not yet know which MAC address owns the IP. The reply identifies the interface that should receive the traffic.

An ARP table stores relationships between IPv4 addresses and MAC addresses. A simplified table might look like this:

IP addressMAC addressMeaning
192.168.1.1AA:AA:AA:AA:AA:01Default gateway
192.168.1.20BB:BB:BB:BB:BB:20Local computer
192.168.1.50CC:CC:CC:CC:CC:50Printer

If Computer A needs to send traffic to 192.168.1.50, it can look up the matching MAC address and send the frame toward that interface through the switch.

For a remote destination, the computer does not need the remote server's MAC address. It needs the MAC address of the local default gateway, because that gateway is the next local hop.

ARP was not designed with strong authentication. An attacker can send false ARP information to devices on the network. The attacker may attempt to convince a victim that:

Victim's IP address → Attacker's MAC address

The victim may then send traffic to the attacker instead of directly to the intended destination. The attacker can potentially forward the traffic afterward, creating an on-path attack.

Normally, communication looks like Victim → Intended destination. With ARP poisoning, it may become Victim → Attacker → Intended destination.

Security impact: confidentiality may be affected if the attacker sees transmitted information; integrity may be affected if the attacker modifies information; and availability may be affected if the attacker disrupts or drops communication.

Remember: ARP poisoning is false ARP information used to redirect traffic.

ARP spoofing is the technique of sending forged ARP messages. ARP poisoning describes the harmful effect of incorrect ARP information being stored or used. In practice, the terms are often discussed together.

An on-path attacker positions themselves between communicating parties and may observe, capture, modify, or forward communication. Encryption can reduce the usefulness of intercepted information because properly encrypted data is much harder to understand.

Network interception + encryption = an important defense against data exposure.

An on-path attacker is not necessarily trying to make the connection stop. They may want the communication to continue while secretly intercepting it.

MAC spoofing occurs when a device changes the MAC address it presents to the network. An attacker may try to impersonate another device, bypass MAC-based restrictions, avoid identification, gain access, or circumvent access controls.

MAC filtering is not a perfect security mechanism because MAC addresses can potentially be spoofed.

MAC flooding attacks a switch's ability to keep track of MAC addresses. A switch maintains a MAC address table that maps devices to switch ports. An attacker sends a very large number of frames containing different MAC addresses to overwhelm that table. If the switch can no longer properly keep track of addresses, it may forward traffic more broadly, allowing the attacker to observe traffic they normally would not receive.

MAC spoofing = pretend to be another interface.
MAC flooding = overwhelm the switch's MAC table.

Organizations can reduce local-network risk with layered controls:

  • Use encryption such as HTTPS and secure wireless encryption so intercepted traffic is harder to understand.
  • Use switch protections such as port security, VLANs, authentication, and limits on connected devices.
  • Use DHCP snooping and dynamic ARP inspection where supported to help identify or block suspicious local mappings.
  • Monitor ARP tables for unexpected changes, duplicate IP-to-MAC relationships, or a gateway MAC address changing unexpectedly.
  • Use network segmentation to limit how far an attacker can move after compromising a device.
  • Use logs, alerts, and intrusion detection to investigate unusual ARP, MAC, or local traffic behavior.

No single control is perfect. MAC filtering alone is weak, and encryption does not stop an attacker from attempting local redirection, but layered controls can reduce exposure and limit impact.

These attacks can work together. An attacker may spoof a MAC address to imitate an approved device, poison ARP information to redirect traffic, conduct an on-path attack to observe communication, and attempt to capture sensitive information. Defenders use encryption, segmentation, switch security, monitoring, and access controls to reduce the risk.

ARP poisoning → traffic redirected → on-path position → possible interception or modification

The goal of this review is not only to memorize terms. It is to explain how IP addressing, MAC addresses, ARP, switches, routers, and security controls interact.

Follow one local request

Computer A wants to send data to Computer B at 192.168.1.20. Computer A checks its ARP cache. If no mapping exists, it broadcasts an ARP request. Computer B replies with its MAC address. Computer A builds a local frame using that MAC address, and the switch forwards the frame toward Computer B. If the destination is outside the local network, Computer A resolves the gateway's MAC address and sends the frame to the router.

Checklist

Remember

IP addresses help packets travel between networks. MAC addresses help frames travel across the current local link. ARP connects the two for IPv4 local delivery.

Key takeaways

  • IP addresses support logical addressing and routing.
  • MAC addresses identify local network interfaces and help switches deliver frames.
  • ARP maps an IPv4 address to a MAC address on the local network.
  • Remote traffic is sent to the local gateway's MAC address, not directly to the remote server's MAC address.
  • ARP poisoning can redirect traffic and create an on-path position.
  • MAC spoofing and MAC flooding exploit weaknesses in local identity and switching.
