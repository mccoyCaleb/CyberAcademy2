3.6 • ACL Tables

Access Control List Tables

An Access Control List (ACL) is a set of rules that determines whether network traffic should be allowed or denied. This lesson teaches how to read ACL tables, evaluate packets from top to bottom, and understand why rule order changes the result.

ProgressRule evaluation
Overview 3.1 3.2 3.3 3.4 3.5 3.6 3.7
Big idea

An ACL is a security guard for network traffic.

You can think of an ACL like a security guard at the entrance to a building. The guard asks where traffic is coming from, where it is going, what it is trying to access, what type of traffic it uses, and what port it is trying to use. The ACL uses this information to decide: ALLOW or DENY.

ACLs are commonly used on firewalls, routers, switches, servers, and network security devices.

Read

Direction and protocol

Identify whether traffic is inbound or outbound, then identify whether it uses TCP, UDP, ICMP, or another protocol.

Match

Port and source

Check the service port and the source address or network. Every relevant condition must match for a normal ACL rule to apply.

Decide

First match wins

ACLs are generally processed from top to bottom. The first matching rule determines the action, and later rules are ignored.

How to read ACL tables

An ACL might look like this:

RuleActionDirectionProtocolPortSource
1AllowInboundTCP80ALL
2DenyInboundTCP22192.168.1.0-192.168.1.255
3AllowInboundICMPALLALL
4DenyInboundALLALLALL

The most important skill is learning to read every column together.

  1. What direction is the traffic going: inbound or outbound?
  2. What protocol is being used: TCP, UDP, ICMP, or something else?
  3. What port is being accessed, such as 22, 53, 80, 443, 25, or 3389?
  4. Where is the traffic coming from? This is the source IP address.
  5. Does the rule allow or deny it?

If all of the other conditions match, the ACL applies the rule.

An ACL is generally processed from Rule 1 to Rule 2 to Rule 3 and so on. The firewall looks for the first rule that matches the packet.

Once it finds a matching rule: STOP. Apply that rule. It does not continue looking at later rules.

1Deny TCP 443 from ALL
2Allow TCP 443 from ALL

A computer using TCP port 443 matches Rule 1, so the result is DENIED. Rule 2 is never reached.

Switch the rules:

1Allow TCP 443 from ALL
2Deny TCP 443 from ALL

The same computer now matches Rule 1, so the result is ALLOWED. Rule 2 never gets used. Earlier matching rules take priority over later matching rules, which is why changing ACL order can completely change what a firewall allows.

Inbound traffic is coming into the device, server, or network. Outbound traffic is leaving the device, server, or network.

Computer → Firewall → Server
Inbound: traffic is entering the protected system.

Server → Firewall → Internet
Outbound: traffic is leaving the protected system.

A rule saying Deny Inbound TCP 443 does not necessarily mean “block all HTTPS traffic everywhere.” It means “block matching TCP port 443 traffic entering this device or interface.” Direction tells you which traffic the rule examines.

TCP is commonly used when reliable communication is important: HTTP port 80, HTTPS port 443, SSH port 22, FTP ports 20/21, and RDP port 3389.

UDP does not establish a connection in the same way TCP does and is often used when speed is important: DNS port 53, DHCP ports 67/68, streaming, and real-time applications.

ICMP is used for network control and diagnostic messages. Ping uses ICMP. ICMP does not use TCP or UDP ports in the normal way, so an ACL might say Allow ICMP ALL ALL; the port column is not meaningful in the same way it is for TCP and UDP.

A port helps identify the network service being accessed. Think of an IP address as the street address of a building and the port as the specific door. 192.168.1.20:443 means IP address 192.168.1.20 and port 443, which generally represents HTTPS.

For an ACL question, do not look at the port alone. Look at protocol + port + source + direction.

The source tells you where traffic originated. If a computer with IP 192.168.45.37 sends traffic, the source is 192.168.45.37.

Computer: 192.168.45.37 → TCP 443 → Server: 10.0.0.50
Source: 192.168.45.37
Destination: 10.0.0.50

If the ACL is installed on the server's firewall, the server may be the destination of the connection. Do not confuse an IP address with a port: 192.168.45.37:443 means IP address plus port.

If an ACL says ALL protocol, ALL port, ALL source, the rule is extremely broad. It can match any protocol, any port, and any source. Deny ALL ALL ALL means deny everything that reaches that rule.

Many ACLs have a final rule similar to DENY ALL. For example:

Allow TCP 80 from ALL
Allow TCP 443 from ALL
Allow ICMP from ALL
Deny ALL from ALL

The firewall allows HTTP, HTTPS, and ICMP, then the final rule blocks everything else. This is the default deny concept: anything that is not explicitly allowed may be denied.

An individual IP address looks like 192.168.45.37, but an ACL can specify an entire network such as 192.168.45.0-192.168.45.255. This represents 256 possible addresses.

A subnet mask tells us which part is the network and which part is the device. With IP 192.168.45.37 and mask 255.255.255.0, the first three sections identify the network and the last section identifies the host. The network is 192.168.45.0/24, with range 192.168.45.0–192.168.45.255.

CIDR notation: 192.168.45.0/24 means the same network as 192.168.45.0 with mask 255.255.255.0. IPv4 addresses contain 32 bits. A /24 leaves 8 host bits, so 2^8 = 256 total addresses.

A /16 means the first two octets identify the network and is equivalent to 255.255.0.0. Therefore 192.168.0.0/16 covers 192.168.x.x.

For network 192.168.45.0/24, address 192.168.45.37 belongs because it is between 192.168.45.0 and 192.168.45.255. Address 192.168.46.37 does not belong because the third octet is different: 192.168.45.x versus 192.168.46.x.

Consider:

Rule 3: DENY | INBOUND | TCP | 443 | 192.168.45.0/24
  • Action: DENY; matching traffic is blocked.
  • Direction: INBOUND; traffic must be coming into the protected device or interface.
  • Protocol: TCP.
  • Port: 443.
  • Source: an IP in 192.168.45.0–192.168.45.255.

Suppose the packet is source 192.168.45.37, protocol TCP, port 443, direction inbound. Compare it with the rule DENY inbound TCP 443 from 192.168.45.0/24:

ConditionPacketRuleMatch?
DirectionInboundInboundYes
ProtocolTCPTCPYes
Port443443Yes
Source192.168.45.37192.168.45.0/24Yes

Everything matches, so the rule applies: DENY.

If the source were 192.168.46.37, the source condition would not match. The firewall would move to the next rule. A rule does not partially apply; the packet needs to satisfy the conditions specified by the rule.

  1. Identify the packet: source IP, destination, direction, protocol, and port.
  2. Start at Rule 1. Do not jump around.
  3. Compare every relevant column: direction, protocol, port, and source.
  4. If it does not match, move to the next rule.
  5. If it matches, stop and apply ALLOW or DENY.
  6. Ignore later rules once a match is found.

Consider this ACL:

1 Allow Inbound TCP 80 ALL
2 Deny Inbound TCP 22 192.168.1.0/24
3 Allow Inbound TCP 443 ALL
4 Deny Inbound ALL ALL ALL

A computer at 192.168.1.25 attempts TCP port 22.

Rule 1 requires TCP port 80, but the packet uses port 22, so it does not match. Rule 2 requires TCP, port 22, and a source in 192.168.1.0/24. The source 192.168.1.25 is inside that network, so everything matches. Result: DENY. Stop.

If the source is 10.0.0.50 and it attempts TCP port 22, Rule 2 does not match because the source is outside 192.168.1.0/24. Rules 1 and 3 also do not match, so Rule 4's catch-all applies: DENY.

Consider:

1 Allow Inbound TCP 22 ALL
2 Allow Inbound TCP 80 ALL
3 Deny Inbound TCP 443 192.168.0.0/16
4 Allow Inbound ICMP ALL ALL
5 Allow Inbound TCP 3306 ALL
6 Deny Inbound TCP 3389 ALL
7 Allow Inbound TCP 443 ALL
8 Allow Inbound TCP 587 ALL
9 Deny Inbound TCP 8140 192.168.45.0/24
10 Deny Inbound ALL ALL ALL

The technician's IP is 192.168.45.37 and they are trying TCP port 443. Rule 1 does not match port 22. Rule 2 does not match port 80. Rule 3 requires DENY, inbound, TCP, 443, and source in 192.168.0.0/16. A /16 covers 192.168.x.x, so 192.168.45.37 belongs. Rule 3 matches and says DENY. The firewall stops there.

Rule 7 says ALLOW TCP 443 from ALL, but the firewall never reaches it because Rule 3 already matched.

If Rule 7 is moved before the specific deny, the beginning becomes:

1 Allow TCP 22 ALL
2 Allow TCP 80 ALL
3 Allow TCP 443 ALL
4 Allow ICMP ALL ALL
...
7 Deny TCP 443 192.168.0.0/16

The technician sends 192.168.45.37 → Server using TCP port 443. Rules 1 and 2 do not match. Rule 3 matches TCP, 443, and ALL, so the result is ALLOW. The firewall stops before reaching the later deny.

This is the big idea of specific versus general rules: overlapping rules are decided by their position.

  • Looking for an Allow without checking earlier rules: ALLOW TCP 443 does not mean port 443 works if an earlier DENY TCP 443 matches.
  • Ignoring the source: DENY TCP 443 ALL applies to everyone, while DENY TCP 443 192.168.1.0/24 applies only to that network.
  • Forgetting direction: inbound and outbound rules do not necessarily evaluate the same traffic.
  • Thinking every rule gets evaluated: once a matching rule is found, stop.
  • Confusing IP addresses with ports: 192.168.45.37 is an IP address, while 443 is a port. 192.168.45.37:443 is an IP address plus a port.

Many organizations use a default-deny approach for ACLs and network access: allow only the traffic that is explicitly required, and block everything else. This is a practical application of least privilege and zero-trust thinking.

Instead of saying “let the internet talk to everything,” the safer model is: “allow only the required ports and services from the required sources.” This reduces the chance of accidental exposure, limits scanning, and simplifies access review.

  • Default allow = broad access, easier to misconfigure, harder to audit.
  • Default deny = narrow scope, more secure, easier to explain and validate.

When an administrator adds a new rule, they usually ask: “What is the minimum necessary access for this service?” If the answer is not clear, the safer default is to deny until the requirement is verified.

  1. Identify the source: who is sending the traffic?
  2. Identify the direction: inbound or outbound?
  3. Identify the protocol: TCP, UDP, or ICMP?
  4. Identify the port: 22, 53, 80, 443, or 3389?
  5. Start at Rule 1; never skip ahead.
  6. Check every condition.
  7. If it does not match, move down.
  8. If it matches, stop and apply ALLOW or DENY.
  9. Remember: the first matching rule determines the action.

Practice the decision

For every ACL question, write down the packet's source, destination, direction, protocol, and port. Start at Rule 1, compare every relevant column, stop at the first match, and apply its action. Do not let a later Allow override an earlier matching Deny.

My notes

ACL memory guide

  • ACL → rules that allow or deny traffic
  • Direction → inbound or outbound
  • Protocol → TCP, UDP, ICMP, or other
  • Port → service or application endpoint
  • Source → where traffic came from
  • ALL → any value in that field
  • First match → action is applied, then stop

Checklist

Remember

Do not stop when you see an Allow or Deny that looks relevant. First check direction, protocol, port, and source. The first complete match wins.

Key takeaways

  • ACLs decide whether matching network traffic is allowed or denied.
  • Evaluate direction, protocol, port, source, and action together.
  • ACLs are generally read from top to bottom, and the first matching rule wins.
  • CIDR notation describes networks such as 192.168.45.0/24 and 192.168.0.0/16.
  • A final default-deny rule blocks traffic that was not explicitly allowed.
