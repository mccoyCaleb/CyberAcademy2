3.7 • Detecting Network Attacks

Detecting Network Attacks

Preventing every attack is unrealistic, so defenders also monitor networks for suspicious behavior. Detection systems look for known attack patterns, unusual behavior, and combinations of events that point to malicious activity.

Big idea

Detection turns logs and traffic into alerts.

Security teams cannot stop every attack in advance, so they monitor network activity for suspicious patterns. Logs, NIDS, NIPS, SIEM, and detection rules help transform raw activity into useful security signals.

Logs

Timeline of activity

Network devices produce logs that record connections, blocked traffic, failed logins, and other security events.

Detection systems

NIDS and NIPS

NIDS detects suspicious activity and generates alerts, while NIPS can block or prevent malicious traffic.

Analysis

Signature vs. anomaly

Security software looks for known patterns or unusual activity compared to a normal baseline.

Monitoring and detection systems

Logs are records of what happened on network devices or systems. They can include blocked connections, unusual login attempts, port activity, and other events.

Analysts use logs to reconstruct what happened and decide whether the behavior was suspicious.

A Network Intrusion Detection System (NIDS) monitors traffic and creates alerts when suspicious activity is detected. A Network Intrusion Prevention System (NIPS) both detects and responds by blocking or preventing the malicious behavior.

Think: NIDS = Detect + Alert, NIPS = Detect + Respond.

A SIEM gathers information from multiple sources such as firewalls, server logs, application logs, and NIDS alerts. This makes it easier to piece together a larger cyber event.

One weak signal may not matter, but several events together may reveal a coordinated attack.

Detection methods

Signature-based detection searches for known patterns of malicious activity. It is effective against known attacks, but it may miss new or modified attacks.

Anomaly-based detection measures activity against a baseline. If traffic suddenly spikes or behaves differently than expected, the system may generate an alert.

This approach can catch unknown attacks, but it can also generate false positives.

Hybrid detection combines signatures and anomaly detection to catch both known attacks and unusual behavior. It can be more effective, but it may also create more alerts and complexity.

False positive: a legitimate event is mistakenly labeled as malicious.

False negative: an attack occurs but is missed by the detection system.

Alert fatigue happens when too many alerts overwhelm analysts and make it harder to find real threats.

Detecting specific attacks

Common indicators

  • Evil twin: unfamiliar wireless networks that closely resemble legitimate ones.
  • Jamming: sudden loss of wireless connectivity or widespread interference.
  • ARP poisoning: unusual ARP messages or unexpected changes to IP-to-MAC mappings.
  • MAC flooding: a large number of different MAC addresses or changes in the switch’s MAC table.
  • DNS poisoning: unusual redirection or sudden drop in traffic to an expected site.
  • Smurf attack: large amounts of ICMP traffic using a broadcast address.

Which statement best describes the purpose of adjusting detection thresholds?

Correct: Detection thresholds must be tuned so the system is sensitive enough to find attacks without overwhelming analysts with unnecessary alerts.

Checklist

Remember

  • Detection is about recognizing suspicious patterns, not just blocking everything.
  • Fake alarms can be just as harmful as missed attacks.
  • A strong SIEM connects events across systems.
  • Network monitoring is part of active defense.
