3.5 • Firewalls

Firewalls

A firewall is a core security control because it inspects and filters network traffic. It decides which traffic should be allowed or blocked based on the source, destination, port, protocol, and rule order.

Big idea

A firewall is a checkpoint.

Traffic arrives at the device, the firewall evaluates the packet or connection, and then decides whether it is allowed or denied. The decisions are made using rules based on source, destination, protocol, port, and direction.

Rules

Decision logic

Firewalls examine fields such as source and destination IPs, port numbers, and protocol to decide what traffic is permitted.

State

Stateless vs. stateful

A stateless firewall examines individual packets, while a stateful firewall tracks the state of a connection.

Advanced features

NGFW

Next-generation firewalls can do traditional filtering plus deeper inspection, threat prevention, and application-aware decisions.

Firewall basics

A firewall acts as a security checkpoint between networks. It evaluates traffic and allows or blocks it according to defined rules.

The firewall can make decisions based on IP addresses, ports, protocol, and connection state.

A stateless firewall evaluates packets individually based on their header information. It does not keep track of the larger connection context.

A stateful firewall keeps track of connection state. It can determine whether a packet is part of an existing communication and make a more accurate decision.

A Next-Generation Firewall (NGFW) adds features beyond basic filtering, including deep packet inspection, intrusion prevention, and application-aware filtering.

ACLs and rule order

An Access Control List (ACL) is a collection of rules. For example, a rule may allow TCP traffic from one IP to another on port 443.

ACLs are the rule set that determines which packets or sessions are allowed.

Firewall rules are evaluated in order. The first matching rule is applied. This is a common AP trap.

Example: If Rule 1 denies all TCP traffic and Rule 2 allows only port 443, then traffic to port 443 will still be denied because Rule 1 matches first.

When reading firewall rules, identify the source, destination, protocol, and port, then start at Rule 1 and ask whether the traffic matches. If it matches, stop and apply that rule.

Firewall rule practice

Checklist

Remember

  • Rule order is often the deciding factor.
  • Port 443 is commonly associated with HTTPS.
  • NGFWs can inspect more deeply than basic packet filter rules.
  • Firewalls are control points, not complete security by themselves.
